Zoho CRM ⇌ Zoho Survey Integration — Pitch Feature Menu
========================================================

Every item passes the "breaks without one side" test — noted why it is
impossible standalone, since that is the core sales argument. The unique
asset is the JOIN: sentiment (Survey) attached to a revenue/process object (CRM).

Use Cases — what the user expects ("As a user, I want…")
========================================================

These are the user stories the integration must satisfy. Grounded in the car
showroom (Kia dealership) running example: surveys sent on deal-stage events
(test-drive done, delivered, serviced), responses auto-linked back to the deal,
and Revenue at Risk computed as Amount x (1 - s), where s is the normalized
sentiment score (NPS / CSAT / purchase-intent, whichever the survey carries).


Sales Manager / Exec — "As a manager, I want…"
----------------------------------------------
UC-M1  …see the TOTAL revenue at risk from customer sentiment, so I know my
       exposure in ₹, not just a satisfaction score.
UC-M2  …see that number TREND over time, so I know if we're getting better or worse.
UC-M3  …see a RANKED list of at-risk deals (by ₹), so I can prioritize intervention.
UC-M4  …SEGMENT at-risk revenue by model / consultant / showroom / stage, so I can
       find the systemic cause.
UC-M5  …read the TOP OBJECTION THEMES from open-text answers, so I fix the root
       cause, not each symptom.
UC-M6  …DELEGATE / bulk-act on a slice of at-risk deals (assign follow-ups), so my
       team acts this week.
UC-M7  …CHANGE the process or config (threshold, which survey, when it fires) and
       WATCH the number move, so I can prove the intervention worked.


Sales Rep (Jay) — "As a rep, I want…"
-------------------------------------
UC-R1  …see an AT-RISK signal on my Deal/Contact, so I know which deals need saving.
UC-R2  …know WHY (the customer's own words), so my recovery call is specific.
UC-R3  …get a NEXT BEST ACTION, so I know what to do without analysis.
UC-R4  …be ALERTED immediately on a negative response, so I act while it's hot.
UC-R5  …FILTER "my at-risk deals" in a CRM list view, so it fits how I already work.
UC-R6  …RECOVER a deal and see its risk flag CLEAR, so my effort shows in the system.


Admin (Jay) — "As an admin, I want…"
------------------------------------
UC-A1  …surveys to AUTO-SEND when a deal stage changes (test-drive done, delivered,
       serviced), so it scales without manual effort.
UC-A2  …every response to AUTO-LINK to the right deal/contact, so I never reconcile
       responses by hand.
UC-A3  …to CONFIGURE the risk threshold and which metric drives it (NPS/CSAT/intent),
       so the signal fits our business.
UC-A4  …to MAP survey answers to CRM fields, so responses enrich the record
       automatically.


Send / scoping rules (frozen for Revenue at Risk)
-------------------------------------------------
- Transactional surveys (test-drive, delivery CSAT, service feedback) → sent from
  the DEAL WORKFLOW on stage change → DEAL-SCOPED, stamps dealId → precise ₹.
- Relationship surveys (NPS check-in) → sent from the CONTACT → RELATIONSHIP-SCOPED
  → spills across that contact's open deals.
- Unit of risk is the DEAL, not the contact: score per deal, sum per deal, never
  multiply a contact's combined deal total by one score (no double-count).
- One signal per deal: if a deal has multiple responses, use the latest / worst-active.
